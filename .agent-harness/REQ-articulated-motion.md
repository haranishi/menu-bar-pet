# REQ: 細切りアニメーション（1枚絵をパーツ分割して走らせる）＋フレーム供給の修正

対象リポ: menu-bar-pet（Swift 6 / SwiftPM / macOS 14+ / AppKit）
起票: 2026-08-29 ／ 前提: REQ-motion-quality.md 合格後の実機確認で「RunCatほど滑らかでない」と本人判定

## 0. 背景（コードを読んでも分からないこと）

原因は2つに切り分け済み。
- **C1**: 高負荷時はサイクル0.30sを15fpsで描く＝**1周期4〜5コマ**。動きでなく瞬間移動に見える。
- **C2**: 1枚絵の剛体変形にはポーズ変化が無い。RunCatの滑らかさの本体はコマ＝ポーズ変化
  （実物確認済み: RunCat365 OSS は cat_0〜4.png の5コマ切替。コード描画ではない）。
方針: **AI・画像解析なしで**、本体画像を固定比率の帯に「細切り」し、帯ごとに位相差のある
動きを毎フレーム合成する（C2）。フレーム供給はサイクル周期に連動させる（C1）。
本人合意: AIコマ生成は第2弾（ローカルモデル前提）。本REQには含めない。

## 1. C1: フレーム供給の修正

- `cycleDuration` の下限を **0.30s → 0.45s** に変更（1周期の最低コマ数確保。旧S1の0.30sを改訂）。
- `framesPerSecond` を state に加え **cpu（平滑化済み）依存**にし、**1周期あたり最低12コマ**を保証:
  `fps = clamp(12 / cycleDuration(cpu), 状態別下限, 30)`（下限: resting 8 / normal・running 12 / sweating・onFire 15）。
- `StatusItemController` は実効fpsが**10%以上変わった時だけ**タイマーを張り替える（毎秒の連打をしない）。
- 位相の連続性は従来どおり（状態変化・タイマー張り替えでリセットしない）。

## 2. C2: 細切り（アーティキュレーション）

本体ビットマップ（**ユーザー画像・標準ペット共通の経路**にする）を body-local 空間（0..1）で帯に分割:

| 帯 | 範囲(y) | 動き（すべて位相の純関数・Coreで計算） |
|---|---|---|
| 脚帯 | 0〜0.34（さらに左右半分に分割） | 水平 dx=±A·sin(2πp)（左右逆符号）。垂直±1.3ptを左右逆相で。Aは状態振幅に比例（resting=0、onFire最大1.6pt） |
| 胴帯 | 0〜0.92（**全高の裏板**として最初に描く） | 現行の潰し伸ばし・傾きを担当 |
| 頭帯 | 0.74〜1.0 | バウンスを位相遅れ（p−0.10）で追従。傾きは胴の**15%**を逆向き（40%は帯端が裂けた＝r2採点で確定） |

- 境界は**重なり**を持たせ切れ目を隠す。分割比率・振幅の定数は MenuBarPetCore に置く。
- 描画（PetRenderer）: 本体を一度**3倍解像度で**ビットマップ化（内部の絶対値定数も追随させる）→
  帯をクロップ（source矩形は整数ピクセル）→ 帯ごとに変形して合成。
  描画順は **胴 → 後脚 → 前脚 → 頭**。影は状態強度（intensity）で脈動を減衰。オーバーレイは本体bboxに重ねない。
- ※上記の太字はラウンド1採点（18/24）→ラウンド2（22/24合格）で確定した改訂値。初版の 胴0.30〜0.78・
  頭傾き40%・脚垂直0.4pt は破綻（腹スリット・頭部裂け・交互に見えない）の原因だったため破棄。
- `reduceMotion` 時は細切りなし（剛体・静止）＝現行維持。
- **禁止**: 画像内容の解析（脚検出・セグメンテーション・被写体判定）。帯は固定比率のみ。

## 3. UX5階層からの追加仕様（3件）

- **S6（要件層）**: 脚の往復は**サイクル周波数のみ**。フレーム単位のランダムなじらつき禁止
  （周辺視野にはチカつきとして刺さる）。
- **S7（戦略層）**: resting では脚を動かさない（呼吸のみ）。「アイドルで邪魔」の一線を守る。
- **S8（構造層）**: 帯は構図が合わない写真（顔だけ・座りポーズ等）でも**破綻しない振幅**に収める。
  最悪ケースで現行の剛体変形と同等以上に見えること＝振幅で壊さない。
