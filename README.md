# MenuBarPet MVP

キャラクターをMacのメニューバーに常駐させ、CPU負荷またはAIの使用枠へ反応させるローカル検証版です。キャラは柴犬・ハムスター・自作ランナーから選べます。macOS 14以降、画面はApple標準フレームワークで動き、外部通信やアカウントはありません。

状態判定・モーション計算・AIログ解析・CPUと通信量の取得はRustで処理します。画面はAppKit／SwiftUIを使い、Macの表示と操作を維持しています。ビルドにはSwiftとRustが必要です。Rustは[公式サイト](https://rustup.rs/)から導入できます。

## すぐ試す

```bash
cd ~/Projects/menu-bar-pet
./scripts/build-app.sh
open dist/MenuBarPet.app
```

概要では使用率と残量、リセット時刻を見られます。設定ではキャラ、数値表示、AI連携を変更できます。

初回ビルド後はFinderで`dist/MenuBarPet.app`をダブルクリックしても起動できます。メニューバーのキャラをクリックするとポップオーバーが開き、動かす指標とキャラを選べます。終了はポップオーバー右下の「終了」です。

ソースから直接起動する場合は、先に`./scripts/build-core.sh`でRustコアをビルドし、`swift run MenuBarPet`を実行します。検証の入口は`./scripts/test.sh`です。

## このMVPで確認できること

- Dockへ出ないメニューバー常駐とキャラ表示
- CPUを1秒ごとに読み、休息・通常・疾走・汗・全力へ変える反応
- 接地・蹴り出し・振り戻しが連続する走行と、状態に合わせた呼吸・前傾
- 一時停止、Reduce Motionへの追従
- ポップオーバーからのキャラ切替
- 設定の再起動後復元

設定はmacOSのUserDefaultsへ保存されます。CPU履歴、アプリ名、キー入力は保存しません。

## AI使用率メーター（Claude Code／Codex）

CPUの代わりに、Claude CodeとCodex CLIの使用枠でキャラを走らせられます。駆動値は有効なプロバイダの全枠の実効使用率（`resets_at`を過ぎた枠は0%）の最大値です。5時間枠だけを見ないのは、不意打ちになりやすいのが週枠の方だからです。上限到達（例`workspace_member_credits_depleted`）を5時間以内に観測したときは、枠の値に関係なく100%として駆動します。使えるデータが無い状態はエラーではなく初回状態として扱い、キャラは休息したまま案内文を出します。

有効にするには、ポップオーバーの「動かす指標」を「AI使用率」へ切り替えます。しきい値は標準（20/50/75/90）です。

AI使用率モードでは、キャラの右に9pt・2行の数値も出ます。1行が1プロバイダで、`Claude  93  24`のように短い枠（5時間）→長い枠（7日）の順で実効値を並べます（%記号なし、片方だけの枠は`--`）。上限に当たっている枠は数字より優先して`Codex  上限`になります。全プロファイルと全枠のリセット時刻はツールチップに出ます。数値が邪魔なら「設定」の「メニューバーに数値を表示」をオフにしてください（既定オン。CPUモードでは出ません）。一時停止で止まるのはアニメと状態機械だけなので、一時停止中も数値は出続けます。

Claude Codeは公式のstatusLine経由で受け取ります。「設定」の「AIの連携」で「連携する…」を押すと、確認ダイアログの後に`settings.json`の`statusLine.command`を`"<MenuBarPet 実行体>" --statusline`へ向けます。書き換える前に`settings.json.menubarpet-backup-<日時>`を作り、既に入っているstatusLineは`--then '<元コマンド>'`として連結するので、元の表示は消えません。戻すときは同じ画面の「解除」を押すか、backupから復元します。シェルやjq・pythonを用意させないために、statusLineに指すコマンドはアプリ自身のモードにしてあります。

Codexは設定不要です。`~/.codex*/sessions/YYYY/MM/DD/rollout-*.jsonl`の`token_count`イベントを、末尾512KBだけ読みます。枠が見つからないときだけ、走査を3日×16本まで広げます。

Claude Codeから受け取ったJSONは`~/Library/Application Support/MenuBarPet/AIUsage/claude-<プロファイル>.json`に保存します。設定ホームが複数ある場合はプロファイルごとに1ファイルです。

```bash
MenuBarPet --statusline [--then '<cmd>']   # Claude Codeから呼ばれる側。所要0.008秒・常にexit 0
MenuBarPet --ai-usage-dump                 # 検出したプロファイルとスナップショットを表示（検証用）
MenuBarPet --menubar-snapshot <dir>        # メニューバー表示をGUIなしでPNG化。文字が0画素ならexit 1
```

制約が4つあります。

- 資格情報とネットワークには一切触れません。キーチェーン・Cookie・使用量APIへの問い合わせはどれも使わず、ローカルのファイルだけを読みます
- `rate_limits`が来るのはPro/Maxという前提で作っています。それ以外のプランでの挙動は未検証です
- 値はセッションで最初の応答が返るまで出ません。Claude Codeを1回も動かしていない日は、キャラが休息したままになります
- ChatGPTの一般チャットは公式の取得手段が無いため対象外です

## 現時点の範囲外

これは販売版ではなく企画のP1〜P2検証版です。自動背景除去・手動クロップ、ログイン時起動、StoreKit、複数ペット、署名・公証・App Sandbox付き配布は未実装です。自作ランナーのコマ画像は透過PNGを推奨します。

## 繰り返し処理を減らす

活動中のキャラを96コマまで再利用し、合成画像も96枚に制限しています。ハムスターは体と回し車を別々に保存するため、回転と足運びが独立します。同じ数値の文字画像を再利用し、集計とツールチップ整形を毎秒1回に抑えています。AIログの読み取りは画面とは別の処理へ移し、閉じたポップオーバーではSwiftUIの画面を外します。システム欄のストレージは30秒、バッテリーは5秒間隔で取得します。

合成データを使った3回の比較では、2000フレームの処理時間が約35%、Codexログ解析が約95%短縮しました。今回の画像再利用では、反復する2000フレームを約211msから約8msへ短縮しました（約96%、合成データ）。アプリ全体の改善率とは別の計測です。条件と実測値は[検証記録](.agent-harness/runs/2026-10-11-rust-performance.md)にあります。

```bash
dist/MenuBarPet.app/Contents/MacOS/MenuBarPet --benchmark 2000
swift scripts/ui-smoke.swift
swift scripts/ui-smoke.swift --soak-seconds 300 --soak-output /tmp/menubar-soak.json
```

UI検証はアプリ起動中に、既存のアクセシビリティ権限で実行します。検証後は元の設定へ戻します。長期常駐、複数画面、スリープ復帰の評価は引き続き必要です。

常駐計測では、幅計算を毎回行う版からレイヤー更新版への変更でCPU中央値が22.35%→1.65%となりました（各5分）。RSSは約107MiB→約118MiBと増えており、メモリの削減は確認できていません。

画面と走行の改善は[追加検証記録](.agent-harness/runs/2026-10-11-smooth-runner-ui.md)にまとめています。
